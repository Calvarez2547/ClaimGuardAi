# ClaimGuard AI v1.1.0

## Summary

`v1.1.0` adds optional real OpenAI provider integration to the backend claim analysis flow while preserving deterministic backend scoring as the source of truth.

## What changed

- added OpenAI provider integration through the official Java SDK
- added an AI provider abstraction layer for future providers
- added prompt construction and structured JSON parsing for AI-assisted reviewer output
- added safe fallback behavior when AI is disabled or provider calls fail
- added AI configuration validation and new environment variables
- added a new Flyway migration to persist structured AI output JSON
- updated tests and documentation for local AI enablement and fallback behavior

## Core design principle

The backend still owns:

- final risk score
- risk category
- deterministic risk factors
- risk weights
- human-review flag
- access control
- persistence

OpenAI assists with reviewer-facing narrative output only.

## Environment variables

- `AI_ENABLED`
- `AI_PROVIDER`
- `AI_API_KEY`
- `AI_MODEL`
- `AI_TIMEOUT_SECONDS`

## Safety and scope notes

- this is a healthcare revenue-cycle claim review prototype
- the AI assists a reviewer and does not replace a human reviewer
- the AI is not making medical decisions
- the AI is not giving clinical advice
- the AI is not making legal decisions
- the AI is not making final payer decisions
- this project does not claim HIPAA compliance
- this project is not production-ready for real PHI
- there is no real payer, EHR, or clearinghouse integration

## Compatibility

- existing claim analysis endpoints remain unchanged
- deterministic fallback behavior remains available
- existing dashboard/reporting flows continue to use persisted deterministic analysis data
